# 文档体系重新设计 任务清单

## 任务优先级说明
- **P0**: 核心产出，必须完成
- **P1**: 重要支撑，尽快完成
- **P2**: 完善优化，可后续完成

---

## P0 — 核心产出

- [x] P0-01: 输出当前文档体系问题诊断报告
  - 梳理11份现有文档的职责边界、内容重复项、口径冲突项、引用失效项
  - 输出问题分类表（严重/中等/轻微）
  - 输出每份文档的"冗余内容"和"缺失内容"清单
  - 验证：诊断报告能清晰回答"当前文档体系哪里出了问题"

- [x] P0-02: 设计五类文档的定位、边界和"应该写什么/不应该写什么"清单
  - 定义开发指导文档、数据库详细设计文档、详细开发细节文档、项目开发资料文档、开发进度文档
  - 为每类文档输出"内容边界表"（包含项 vs 排除项）
  - 验证：任意一段现有文档内容，能够明确归类到五类之一

- [x] P0-03: 设计文档间引用关系图
  - 定义主文档到子文档的跳转规则
  - 定义子文档之间的交叉引用规则
  - 输出引用关系矩阵
  - 验证：从任意功能点出发，能在2步内定位到最细节文档

- [x] P0-04: 制定"开发指导文档"推荐目录结构
  - 覆盖：项目目标与业务边界、系统核心原则、邮件处理总体流程、工单状态机总览、文档引用规则、后端分层架构、前端模块边界、数据库设计原则、AI/规则/人工职责边界、附件处理原则、开发优先级、测试验收、禁止事项
  - 每个章节标注是"写摘要"还是"写完整内容"，以及跳转到的子文档
  - 验证：目录结构可作为新主文档的骨架直接使用

- [x] P0-05: 制定文档维护规则
  - 定义变更同步规则（业务流程变/数据库字段变/接口变/前端页面变 → 需同步哪些文档）
  - 定义冲突裁定规则（文档与代码冲突、文档之间冲突、新旧文档冲突）
  - 定义变更历史记录格式
  - 验证：任意一种常见变更场景，维护规则能明确指导操作

## P1 — 重要支撑

- [x] P1-01: 制定现有文档迁移方案
  - 明确哪些文档保留（作为专项文档继续维护）
  - 明确哪些文档降级（标记为"历史存档"不再维护）
  - 明确哪些文档内容需要提取到新文档
  - 输出迁移映射表（旧文档 → 新文档/存档/删除）
  - 验证：迁移后每份保留文档有明确归属类别，无遗漏

- [x] P1-02: 制定文档命名与版本管理规范
  - 定义文档命名规则（前缀/后缀/版本号）
  - 定义更新时间戳格式
  - 定义文档头部的"当前实现基线"模板
  - 验证：新文档模板可直接复用

## P2 — 完善优化

- [x] P2-01: 输出文档治理方案总览文档
  - 将P0-01至P1-02的产出汇总为一份"文档治理方案总览"
  - 包含：问题诊断 → 新体系设计 → 文档边界 → 引用关系 → 维护规则 → 迁移方案
  - 验证：新加入项目的成员读这份方案即可理解整个文档体系

# 任务依赖关系

- P0-01（问题诊断）是 P0-02/P0-03/P0-04/P0-05 的前置输入
- P0-02/P0-03 可并行（文档边界和引用关系独立设计）
- P0-04（主文档目录结构）依赖 P0-02（文档边界已明确）
- P0-05（维护规则）依赖 P0-03（引用关系已明确）
- P1-01（迁移方案）依赖 P0-02/P0-03（新体系已确定）
- P1-02（命名规范）独立可并行
- P2-01（总览文档）依赖所有P0和P1完成

# 任务并行化建议

- P0-02 和 P0-03 可同时执行
- P0-04 和 P0-05 可同时执行（P0-02依赖已完成后）
- P1-01 和 P1-02 可同时执行
