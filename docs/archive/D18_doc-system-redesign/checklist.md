# 文档体系重新设计 验证检查清单

## 问题诊断产出一致性
- [x] 诊断报告覆盖全部11份现有文档
- [x] 每份文档标注了：当前职责、实际内容类别、冗余内容、缺失内容
- [x] 问题分类表包含严重/中等/轻微三级，每级有具体数量
- [x] 冲突项有"文档A说X → 文档B说Y → 代码实际是Z"的三方对比
- [x] 引用失效项有"文档A引用文档B → 文档B不存在/路径错误"的明确记录

## 五类文档边界清晰性
- [x] 每类文档有独立的"应该包含"清单（至少5项）
- [x] 每类文档有独立的"不应包含"清单（至少3项）
- [x] 任意两份文档的"应该包含"清单无重叠
- [x] 现有文档中任意一段内容，能被归类到五类之一（无"无处归属"的内容）
- [x] 现有文档中任意一段内容，不会被归类到两类以上（无"两头归属"的内容）

## 文档间引用关系完整性
- [x] 引用关系图覆盖所有5类文档
- [x] 每类文档标注了"被哪些文档引用"和"引用哪些文档"
- [x] 主文档中每个"摘要"章节标注了跳转到哪个子文档的哪个章节
- [x] 任意业务概念，从主文档出发最多2步引用可到达最细节处

## 开发指导文档目录结构可操作性
- [x] 目录覆盖了用户指定的16个主题领域
- [x] 每个章节标注了内容形式（摘要/完整/跳转链接）
- [x] 每个"跳转链接"指向实际存在的子文档或计划创建的文档
- [x] 目录结构层次不超过3级
- [x] 新成员能在15分钟内通过目录找到目标信息

- [x] 维护规则能用流程图或表格表达，非纯叙述文本

## 迁移方案可落地性

- [x] 迁移后无文档内容丢失（提取覆盖所有旧文档的业务知识）

- [x] 方案包含了问题诊断 → 体系设计 → 维护规则 → 迁移方案 完整闭环
