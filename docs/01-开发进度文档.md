# 邮件报修自动化系统开发进度文档

## 0. 文档定位

本文档是项目当前状态、任务进度、风险和下一步计划的唯一正式记录。Codex 或其他 AI 开发助手每次开始开发任务前，必须阅读本文档，确认当前项目状态和任务上下文。

适用场景：

- 开始一个新开发任务前确认当前阶段。
- 判断某项能力是否已完成、开发中、待开发或阻塞。
- 开发结束后记录实际变更、验证结果和后续建议。
- 代码与文档冲突时记录冲突和处理结论。

何时查阅：

- 每次开发任务开始前必须查阅。
- 每次开发任务结束后必须更新。
- 任务优先级、阻塞项或验收状态变化时必须更新。

维护规则：

- 只记录当前状态和任务，不重复数据库字段、接口细节、业务模板。
- 已完成、开发中、待开发必须分开写。
- 后期计划必须标明“未落地”或“后续目标”，不能混入已完成能力。
- 不记录真实密钥、密码、邮箱凭据、OSS key、AI key。

## 1. 当前阶段

当前阶段：内部试运行闭环硬化。

> 2026-07-13：已完成项目文档治理P0阶段（归档旧文档、合并重复内容、建立精简6文档体系）。

总体结论：

- 基础业务、DeepSeek AI 首轮接入、用户管理、个人信息、站内消息、解析结果应用状态、人工处理流程、接口级 RBAC、统计分析、运行时配置已完成本地开发和验证。
- 当前项目已经具备以下基础业务闭环：
  1. 手工邮件入库或既有邮件查询。
  2. 规则预解析生成候选和上下文，DeepSeek AI 作为邮件业务判断必经环节生成最终解析候选。
  3. 工单字段、明细、附件、邮件时间线、字段证据、状态日志展示。
  4. 工单字段编辑、明细编辑、SN 校验。
  5. 高置信且无冲突的 AI 解析结果自动应用；低置信、缺字段、字段冲突、AI 不可用等情况进入人工复核。
  6. 人工复核任务进入统一任务池，支持全员可见、操作员领取、主管分配/转派、释放、处理、重解析。
  7. 追问/确认回复草稿生成，AI 不可用时回退模板。
  8. 回复草稿编辑；人工确认后发送，生产可通过配置切换满足条件自动发送。
  9. 站内通知支持全局任务池通知、指定用户通知和角色通知。
- 当前主要缺口不在核心业务 CRUD，而在自动化入口、附件归档、调度、关联查询、冲突检测、E2E 和后期 LangGraph 编排。

## 5. 后期 LangGraph 路线

LangGraph 是后期 Agent 工作流开发计划，不属于当前已落地能力。

P0：最小可运行闭环

- 新增 `backend/app/graphs/`。
- 建立 `EmailRepairGraph`。
- 手工入库邮件后可触发 Graph。
- 复用当前 parser、ai、tickets service。
- 返回 `graph_run_id`、执行状态和结果摘要。

P1：核心业务工作流节点

- 邮件加载、正文预处理、规则粗分类、附件识别、AI 全量解析、schema 校验、业务校验、工单动作计划、人工复核判断、回复草稿节点。
- 引入 Conditional Edge，实现业务邮件、无关邮件、低置信、缺字段、冲突、人工复核等路径。
- Graph 不直接改状态，状态流转必须调用 `WorkflowService`。

P2：异常、日志、持久化、人工兜底

- 新增 `graph_runs`、`graph_node_logs`、`langgraph_checkpoints`、`langgraph_checkpoint_writes`。
- 支持节点级日志、耗时、重试次数、错误原因、输入输出摘要。
- 支持人工 interrupt/resume。
- 大文本不进入节点日志，只保存引用。

P3：优化、扩展、多模型适配、监控统计

- Qwen OCR / Qwen VL 多模态节点。
- 节点耗时、成本、失败率统计。
- 批量邮件并发控制。
- 多模型路由和 Prompt 版本管理。
