## 二、新文档体系设计

### 2.1 体系总览

```
                          ┌──────────────────────────┐
                          │    开发指导文档（主文档）    │
                          │  项目唯一全局入口，定义     │
                          │  原则、方向、边界、架构     │
                          └───────────┬──────────────┘
                                      │ 引用跳转
            ┌─────────────┬───────────┼───────────┬─────────────┐
            ▼             ▼           ▼           ▼             ▼
    ┌───────────┐  ┌───────────┐ ┌───────────┐ ┌───────────┐ ┌───────────┐
    │ 数据库详细 │  │ 详细开发  │ │ 项目开发  │ │ 开发进度  │ │ 部署运维  │
    │ 设计文档   │  │ 细节文档  │ │ 资料文档  │ │ 文档      │ │ 文档      │
    │           │  │           │ │           │ │           │ │           │
    │ 表/字段/  │  │ 模块/接口 │ │ 模板/样例 │ │ 任务/进度 │ │ compose/  │
    │ 索引/约束  │  │ /页面/服务│ │ /术语/    │ │ /风险/    │ │ nginx/    │
    │ /枚举/迁移 │  │ /工作流   │ │ Prompt    │ │ 迭代记录  │ │ CI/CD     │
    └───────────┘  └───────────┘ └───────────┘ └───────────┘ └───────────┘
```

### 2.2 文档定位

| 文档类别 | 核心定位 | 目标读者 | 唯一性 |
|---------|---------|---------|:-----:|
| **开发指导文档** | 项目全局入口，定义原则/方向/边界/架构 | 所有开发人员、AI编程助手 | **主文档** |
| **数据库详细设计文档** | 表结构、字段、约束的细节字典 | 后端开发、DBA | 子文档 |
| **详细开发细节文档** | 模块/接口/页面/服务的实现落地说明 | 具体模块开发人员 | 子文档 |
| **项目开发资料文档** | 业务素材库（模板、样例、Prompt、数据字典） | 所有开发人员 | 子文档 |
| **开发进度文档** | 任务拆分、进度追踪、风险记录 | PM、开发人员、AI编程助手 | 子文档 |
| **部署运维文档** | Docker/Nginx/CI/CD/环境配置 | 运维、部署人员 | 子文档 |

### 6.2 冲突裁定规则

| 冲突类型 | 优先级 | 裁定方式 |
|---------|:-----:|---------|
| 代码 vs 文档 | **代码为准** | 文档同步更新为代码实际值，记录变更历史 |
| 开发指导 vs 子文档 | **开发指导为准** | 子文档需修正，子文档只能更细节但不能违反开发指导的原则 |
| 子文档 vs 子文档 | **数据库设计文档优先** | 数据库字段和枚举定义以D5为准，其它冲突需人工裁定 |
| 新旧文档 | **新版替代旧版** | 旧版标记为"历史存档"并在头部注明被替代 |
| 代码实现 vs 产品需求(PRD) | **PRD为方向** | 代码偏离PRD需确认是"合理简化"还是"需求变更"，记录为设计决策 |

## 附录：关键术语对照

| 中文术语 | 英文表名/字段名 | 定义 |
|---------|---------------|------|
| 工单 | `repair_tickets` | 报修业务处理对象，一张工单可包含多条明细 |
| 邮件线程 | `email_threads` | 同一报修对话中多封邮件的容器，不等同于工单 |
| 解析结果 | `parse_results` | 规则/AI/人工产生的结构化字段候选，非工单最终视图 |
| SN校验 | `sn_validation_results` | 对工单每行明细的SN进行资产库存在性/有效性/客户/物料匹配校验 |
| 人工复核任务 | `manual_review_tasks` | 需要人工介入的处理事项，含领取/分配/处理/重解析 |
| 追问草稿 | `reply_records` | 向客户发送补充信息邮件的记录，覆盖草稿→审核→发送全阶段 |
| 乐观锁 | `repair_tickets.version` | 防止多人并发覆盖工单字段的机制 |
| L0/L1/L2 | 处理分层 | L0=基础预处理(不调AI)，L1=轻量分类，L2=专业字段解析+SN校验 |
