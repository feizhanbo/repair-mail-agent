## 2. 项目启动命令

### 2.1 本地后端启动

```bash
cd backend
uvicorn app.main:app --host 0.0.0.0 --port 8000 --reload
```

### 2.2 本地前端启动

```bash
cd frontend
npm run dev          # Vite dev server，监听 0.0.0.0
npm run build        # 生产构建
npm run preview      # 预览生产构建
npm run typecheck    # TypeScript 类型检查
```

### 2.3 数据库迁移

```bash
cd backend
alembic upgrade head       # 执行所有未应用的迁移
alembic downgrade -1       # 回退最近一次迁移
```

### 2.4 种子数据初始化

```bash
cd backend
python -m app.seed
```

种子数据包括：工作流状态、工作流转换规则、角色、默认管理员、基础回复模板。

### 5.2 上游定义

```nginx

```

### 5.3 日志

- `access_log`：`/var/log/nginx/access.log`
- `error_log`：`/var/log/nginx/error.log`

### 5.4 代理头部

所有 proxy_pass 均携带：`Host`、`X-Real-IP`、`X-Forwarded-For`、`X-Forwarded-Proto`。

当前未配置 SSL/TLS，监听 80 端口。SSL 配置（规划中/未实现）。

### 5.5 文件上传代理

- `client_max_body_size` 为 `512m`，用于允许包含多个附件的 EML 请求进入后端；应用层仍按单附件 50MB 等业务限制处理，不能把 Nginx 上限当作自动解析上限。
- `/api/` 使用 `proxy_request_buffering off`，读写超时为 600 秒。生产环境推荐走异步 EML job，避免浏览器连接承担附件解析和 AI 调用耗时。
- 413、OSS 归档失败和 job 失败必须由前端显示明确原因，不得静默丢弃文件。

### 8.4 AI JSONL 日志

AI 调用日志以 JSONL 格式写入本地文件系统，路径规则：

```text
logs/ai/{年}/{月}/{日}/ai-{YYYYMMDD}.jsonl
```

例如：`logs/ai/2026/07/13/ai-20260713.jsonl`

每条记录为一行 JSON，记录 AI 调用类型、完整文本 Prompt/请求/响应、解析结果、Token 用量和耗时；数据库 `ai_call_logs` 仅保存检索摘要与文件定位。

AI JSONL 仅供管理员受审计查看和提示词优化，默认保留 30 天。必须移除密钥、认证头、完整签名 URL 查询串、data/base64 和附件二进制；数据库日志仍不得保存正文、附件全文或完整模型请求响应。六类数据库日志分工固定为：AI 调用写 `ai_call_logs`，用户操作写 `operation_logs`，工单状态写 `ticket_status_logs`，字段变更写 `field_audit_logs`，技术事件写 `system_event_logs`，异步任务写 `job_run_logs`。

> 注意：当前仅在容器本地文件系统记录，未挂载为 Docker 数据卷。容器重建后历史 AI 日志会丢失（规划中/未实现持久化挂载）。

## 9. 数据库备份与恢复

### 9.1 备份命令

```bash
docker exec repair-mysql mysqldump -uroot -p repair_system_dev > backup/repair_system_dev_$(date +%Y%m%d_%H%M%S).sql
```

### 9.2 恢复命令

```bash
docker exec -i repair-mysql mysql -uroot -p repair_system_dev < backup/xxx.sql
```

### 9.3 注意事项

- 以上命令中的密码需交互输入或通过环境变量传入，**不得**将真实密码写入命令历史或文档。
- 生产/试运行环境部署前必须执行备份。
- `backup/` 目录已列入 `.gitignore`，不会进入 Git 仓库。
- 当前 `deploy.sh` 未集成自动备份步骤（规划中/未实现）。

### 9.4 远程数据库 SSH 隧道验证

- 远程 MySQL 镜像只允许通过 SSH 隧道访问，本地连接地址使用 `127.0.0.1:<LOCAL_TUNNEL_PORT>`。
- SSH 主机、用户、私钥/密码、远端 MySQL 端口和数据库密码必须通过本地环境变量或交互输入提供，不得写入脚本、命令历史、文档或测试快照。
- `DB_SMOKE_DATABASE_URL` 应指向本地隧道端口；未配置时数据库 smoke test 必须跳过，不得回退连接任意本地或远程数据库。
- 验证范围包括 Alembic head、27 张业务表、关键索引/外键、`business_emails` 视图和只读 `SELECT 1`，不得执行迁移或数据修改。

异步 SQLAlchemy/MySQL 约束：

- ORM 基类启用 `eager_defaults`，需要在 flush 后使用的服务端默认字段必须随 INSERT 或显式刷新取得，禁止属性访问触发隐式异步 IO。
- worker 的附件阶段使用短事务提交；调用 OSS 或 AI 时不得长期持有数据库锁。失败重试必须基于 job 幂等键和附件终态恢复。
- 真实业务链路验收允许按测试计划保留数据，但必须明确数据库名、来源样本和是否发送邮件；回滚式 schema smoke 仍不得持久化测试行。

## 11. 文档同步门禁

## 12. SQL Server、迁移和 SMTP 授权门禁

- SQL Server 配置包括主机、端口、数据库、账号、密码、ODBC Driver、加密/证书、SN 源字段映射和结果目标映射；状态接口不得返回密码。
- `RELAY_SQLSERVER_ENABLED=false` 时必须做到零 ODBC、零网络、`relay_export_status=not_required`、不创建真实导出任务。
- 自动测试只允许 mock SQL 连接，并检查标识符白名单和参数绑定；不得用字符串拼接业务值。
- 当前数据库版本为 `d5e9f7a2b4c6`。执行 `alembic upgrade` 前必须展示目标版本、表/索引变化、备份建议、锁表风险和回滚方案，并取得独立授权。
- RMA 测试邮件的离线预检与真实发送是两个步骤。只有 From=`rmatest1@accotest.com`、To=`rmatest2@accotest.com`、Cc/Bcc 为空、白名单只含该收件人且预检通过后，才能再次请求发送授权。
- SMTP 测试授权不能替代迁移授权，迁移授权也不能替代 SMTP 测试授权；未授权时不得连接 SMTP，禁止自动重试。
