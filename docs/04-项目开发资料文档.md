# 邮件报修自动化系统项目开发资料文档

> 最后更新时间：2026-07-13

## 0. 文档定位

本文档是业务资料和辅助开发资料库，不承担开发规范职责。全局规范查 `docs/00-开发指导文档.md`，进度查 `docs/01-开发进度文档.md`，数据库细节查 `docs/02-数据库详细设计文档.md`，模块实现查 `docs/03-详细开发细节文档.md`。

适用场景：

- 需要业务术语、邮件样例、工单样例。
- 需要回复话术模板、AI Prompt 原则、结构化输出样例。
- 需要 LangGraph 后期 Prompt、工具调用、OCR/VL、多模态资料索引。
- 需要整理常见异常场景。

何时查阅：

- 开发邮件解析、AI、回复草稿、业务规则、示例数据时查阅。
- 写测试样例或 mock 数据时查阅。
- 调整 Prompt 或话术模板时查阅。

维护规则：

- 只记录业务资料、样例、模板、Prompt 原则。
- 不记录数据库字段全量细节和接口实现细节。
- 不记录真实客户隐私、真实邮件全文、真实密钥、邮箱密码、OSS key、AI key。
- 示例数据必须脱敏。

## 1. 业务术语

| 术语 | 说明 |
| --- | --- |
| 报修邮件 | 客户或内部人员发送的维修/RMA 相关邮件 |
| 系统邮箱 | 用于接收报修邮件的邮箱账号 |
| 邮件线程 | 同一邮件回复链或同一业务上下文的邮件集合 |
| 工单 | 一次报修业务闭环的结构化记录 |
| 工单明细 | 工单中每台设备或每个 SN 的维修明细 |
| SN | 设备序列号，用于资产校验 |
| 板卡规则 | 判断某些物料是否需要寄北京的基础资料 |
| 解析结果 | 规则或 AI 从邮件中抽取出的结构化候选 |
| 缺失字段 | 继续处理前必须补充的信息 |
| 冲突字段 | 邮件、附件、资产库或格式之间存在矛盾的信息 |
| 人工复核 | AI 或规则无法可靠处理时由人工介入 |
| 追问 | 向客户请求补充 SN、故障描述、联系方式等信息 |
| 可导出 | 当前代码口径下，工单字段确认且 SN 校验通过，可导出或同步下游 |
| Agent 工作流 | 后期使用 LangGraph 编排邮件处理步骤的状态化流程 |

## 2. 邮件类型和意图类型

当前代码使用或规划的邮件意图：

| 意图 | 说明 | 当前处理 |
| --- | --- | --- |
| `new_repair` | 新报修请求 | 进入解析、建单或人工复核 |
| `customer_supplement` | 客户补充信息 | 关联线程和工单，线程级重新聚合 |
| `normal_reply` | 普通回复 | 关联线程，不要求本封重复 SN 或故障描述 |
| `rma_sent` | RMA 已发送 | 记录外发事件，不重复生成 RMA |
| `device_received` | 设备已收到 | RMA 已发送时关闭，否则记录延迟事件 |
| `internal_forward` | 内部转发 | 进入 AI 判断和人工兜底 |
| `irrelevant` | 明确无关邮件 | 可跳过业务处理 |
| `unknown` | 类型不明确 | 进入 AI 或人工复核 |
| `outbound_reply` | 系统外发回复归档 | 出站邮件归档 |

后续可扩展意图：

- `repair_device_received`
- `repair_device_returned`
- `customer_receipt_confirmed`
- `export_or_sync_notice`

这些后续意图需要先完成业务事件契约和页面入口；优先由现有状态、操作及系统日志聚合表达，只有证据表明无法满足约束和查询时才评估新表。

## 3. 报修字段说明

工单主字段：

| 字段 | 业务含义 |
| --- | --- |
| 客户编码 | 客户在资产库或业务系统中的编码 |
| 客户名称 | 客户公司或组织名称 |
| 联系人 | 报修联系人 |
| 联系电话 | 可联系客户的电话号码 |
| 联系邮箱 | 可回复客户的邮箱，缺失时可使用来信地址作为候选 |
| 报修日期 | 客户发起报修或系统接收报修日期 |
| 邮寄地址 | 设备或板卡寄送地址 |
| 故障描述 | 客户描述的故障现象 |
| 附件说明 | 邮件附件中的补充资料 |

工单明细字段：

| 字段 | 业务含义 |
| --- | --- |
| SN | 设备序列号 |
| 物料编码 | 设备或板卡物料编号 |
| 物料名称 | 设备或板卡名称 |
| 数量 | 报修数量 |
| 故障现象 | 单台设备或单个 SN 的故障描述 |
| 数据信息 | 客户提供的数据、日志、截图摘要 |
| 备注 | 人工补充信息 |

## 4. 示例邮件

### 4.1 新报修邮件

```text
主题：设备报修申请 - SN ABCD123456

您好，

我司有一台设备需要报修：

客户名称：示例科技有限公司
联系人：张三
联系电话：13800000000
设备 SN：ABCD123456
故障现象：设备上电后无法启动，前面板指示灯异常闪烁。
邮寄地址：上海市示例路 100 号

请协助处理，谢谢。
```

期望识别：

- `intent_type=new_repair`
- 抽取客户、联系人、电话、SN、故障描述、地址。
- 若 SN 在资产库存在且状态有效，后续可进入校验通过路径。

### 4.2 客户补充信息邮件

```text
主题：Re: 请补充报修信息：RMA202607090001

您好，

补充 SN：ZXCV987654
故障描述：运行约 10 分钟后自动断电。

谢谢。
```

期望识别：

- `intent_type=customer_supplement`
- 根据 `In-Reply-To` 或主题归并到已有线程。
- 更新已有工单字段或创建解析候选。

### 4.3 无关邮件

```text
主题：产品活动订阅通知

这是一封市场活动邮件，如需退订请点击 unsubscribe。
```

期望识别：

- `intent_type=irrelevant`
- `parse_status=skipped`
- 不创建工单。

### 4.4 内部转发邮件

```text
主题：Fwd: 客户反馈设备故障

请帮忙看下客户这台设备是否需要走报修流程。

---------- Forwarded message ---------
客户说设备 SN A1B2C3D4 无法开机。
```

期望识别：

- `intent_type=internal_forward`
- AI 判断是否应进入报修流程。
- 低置信或上下文不足时转人工。

## 6. 常见异常场景

| 场景 | 处理原则 |
| --- | --- |
| 缺少 SN | 进入缺失字段，生成追问草稿或人工复核 |
| SN 不存在 | SN 校验失败，进入人工复核 |
| SN 状态非 valid | SN 校验失败，进入人工复核 |
| 客户与 SN 资产不匹配 | 标记 warning，进入人工复核 |
| 邮件类型不明确 | AI 判断；仍不明确则人工复核 |
| AI 低置信 | 人工复核 |
| AI 返回 JSON 不合法 | 后续可重试，当前应转人工或记录失败 |
| 压缩附件 | ZIP/RAR/7Z/TAR/TAR.GZ/TGZ/GZIP 作为工程辅助资料原样私有归档，不解压、不调用模型、不阻塞 RMA；界面标记未经内容扫描 |
| 超大附件 | 后续按附件上限策略转人工 |
| 一封邮件多个报修请求 | 当前建议人工复核，后续可由 LangGraph 拆分动作计划 |
| 已关闭线程收到新邮件 | 当前需人工判断是否新报修，后续可由事件模型辅助 |
| 回复发送失败 | 创建人工复核任务 |
| 状态流转不合法 | 拒绝流转，记录错误 |

## 7. 回复话术模板

### 7.1 缺失信息追问

模板编码：`missing_info_zh`

```text
主题：请补充报修信息：{{ ticket_no }}

您好，

我们已收到您的报修邮件，但还需要补充以下信息后才能继续处理：
{{ missing_fields }}

请直接回复本邮件补充上述内容。谢谢。
```

适用：

- 缺少 SN。
- 缺少故障描述。
- 缺少联系方式。
- 缺少必要地址或客户信息。

### 7.2 SN 信息需确认

模板编码：`sn_invalid_zh`

```text
主题：请确认设备 SN：{{ ticket_no }}

您好，

您提供的设备 SN 暂未通过系统校验，请确认 SN 是否完整、是否存在大小写或字符录入错误。
请回复正确 SN 后，我们会继续处理您的报修申请。
```

适用：

- SN 不存在。
- SN 格式疑似异常。
- SN 与资产库信息冲突。

### 7.3 人工审核提醒

模板编码：`manual_review_notice_zh`

```text
主题：报修邮件需人工确认：{{ ticket_no }}

您好，

您的报修邮件已进入人工确认流程。我们会尽快核对信息，并在需要时联系您补充材料。
```

适用：

- 解析置信度不足，需人工核对。
- 字段冲突或 SN 异常需人工确认。
- 邮件类型不明确或上下文不足。

注意：

- 普通回复默认需要人工审核，受 `AUTO_SEND_ENABLED=false` 控制。
- 新报修首次通过完整安全闸门后，RMA 默认自动生成发送，受独立的 `RMA_AUTO_SEND_ENABLED=true` 控制。
- 回复不能承诺具体维修结果。
- 当无匹配模板时，代码层会生成 fallback receipt（受理确认），该 receipt 不由数据库模板驱动。

## 8. AI 解析 Prompt 原则

系统提示词原则：

- AI 是结构化解析助手，只能输出 JSON。
- 规则解析只作为候选上下文，不直接决定最终业务类型。
- 必须输出意图、字段、明细、缺失字段、冲突字段、置信度、字段置信度、证据。
- 不得编造不存在的信息。
- 不确定字段必须放入 `missing_fields` 或 `conflict_fields`。
- 低置信或需要人工时，必须给出人工复核方向。

输出字段建议：

```json
{
  "intent_type": "new_repair",
  "extracted_fields": {
    "customer_name": "示例科技有限公司",
    "contact_person": "张三",
    "contact_phone": "13800000000",
    "contact_email": "zhangsan@example.com",
    "problem_description": "设备无法启动"
  },
  "extracted_items": [
    {
      "line_no": 1,
      "sn": "ABCD123456",
      "material_code": null,
      "material_name": null,
      "quantity": 1,
      "failure_description": "设备无法启动"
    }
  ],
  "missing_fields": {},
  "conflict_fields": {},
  "confidence_score": 0.86,
  "field_confidences": {
    "sn": 0.9,
    "problem_description": 0.85,
    "contact_email": 0.8
  },
  "evidence": {
    "sn": "原文片段中的 SN ABCD123456",
    "problem_description": "原文片段中的设备无法启动"
  },
  "confidence_reasons": [
    "邮件包含明确报修关键词",
    "SN 和故障描述完整"
  ],
  "manual_review_direction": null,
  "original_evidence": [
    "设备 SN：ABCD123456",
    "故障现象：设备上电后无法启动"
  ]
}
```

禁止：

- 输出非 JSON。
- 输出 Markdown 包裹 JSON。
- 使用模型猜测客户编码。
- 隐瞒冲突。
- 把低置信结果标成高置信。

多 Provider 支持：

- DeepSeek 是邮件级业务结构化解析 Provider，汇总正文、规则候选和附件解析结果。
- Qwen 已作为附件级 Provider 接入。`txt/csv/html/docx/xlsx` 和文本型 PDF 先本地抽取再交给 Qwen；图片和扫描 PDF 使用 OSS 短期预签名 URL 调用 Qwen VL。
- 文本类附件使用 `QWEN_MODEL`，图片和扫描 PDF 使用 `QWEN_VL_MODEL`；VL 未配置时转人工，不回退到文本模型。
- DeepSeek 不接收附件二进制。管理员受限 AI JSONL 可保存完整文本语义用于 Prompt 优化，但不得保存签名参数、密钥、认证头、data/base64 或附件二进制。

附件级输出格式：

```json
{
  "file_type": "pdf",
  "summary": "附件描述一台设备无法启动",
  "key_points": ["包含设备 SN", "包含故障现象"],
  "extracted_fields": {
    "sn": "ABCD123456"
  },
  "extracted_items": [],
  "raw_text": "已截断的附件抽取文本",
  "warnings": ["PDF_TRUNCATED_TO_15_PAGES"],
  "truncated": true
}
```

附件处理规则：

| 文件类型 | 处理方式 | 默认限制 |
| --- | --- | --- |
| `txt`、`csv`、`html` | 本地解码/表格抽取/HTML 转文本后调用 Qwen | 模型输入最多 20000 字符 |
| `docx` | 从 OOXML 提取段落后调用 Qwen | 损坏或加密文件转人工 |
| `xlsx` | 只读抽取前 10 个 sheet，每表前 200 行、40 列 | 超出范围在结果中提示截断 |
| 图片 | OSS 预签名 URL 调用 Qwen VL | 单文件自动解析上限 50MB |
| PDF | 前 15 页先抽文本；无文本时生成前 15 页预览并调用 Qwen VL | 超页标记 `truncated=true` |
| ZIP、RAR、7Z、TAR、TAR.GZ、TGZ、GZIP | 扩展名、MIME、魔数联合识别后原样私有归档 | 不读取目录、不解压、不调用 Qwen；`parse_status=skipped` |

异常结果约定：

- 超过 50MB：保留 OSS 对象，`parse_status=needs_manual_review`，`parse_error=FILE_TOO_LARGE_FOR_AUTO_PARSE`。
- 装饰性 inline 图片：归档前按尺寸阈值剔除，不创建独立 OSS/附件/Qwen 记录；业务内嵌图片正常归档和预览。
- 工程辅助压缩附件：`parse_status=skipped`、`parse_error=null`、`security_status=unscanned_archive`，跳过原因为 `ENGINEERING_REFERENCE_NOT_REQUIRED`，不得触发人工复核或客户追问。
- 其他不支持类型：`parse_status=unsupported`，`parse_error=UNSUPPORTED_FILE_TYPE`。
- 未归档附件：`parse_status=needs_manual_review`，`parse_error=ATTACHMENT_NOT_ARCHIVED`。
- Qwen 超时、服务错误或 JSON 校验失败：保留本地抽取文本和 warning，对应附件转人工，不阻断 DeepSeek 处理邮件正文。
- Qwen 常见形状漂移（对象型摘要、单对象明细、字符串型列表/布尔值）先归一化到附件标准 JSON；无法归一化时保留脱敏后的完整语义请求和模型响应，禁止记录 API Key、二进制 data URL 或完整 OSS 签名查询串。
- 超时、429 和 5xx 最多重试 3 次；模型返回无效 JSON 时只允许一次纠正调用，每次尝试均写 `ai_call_logs`。
- DOCX/XLSX 的 OOXML 本地抽取继续使用现有资源限制；独立压缩附件不打开成员目录，因此不配置压缩层级、成员数量或解压大小。加密 PDF、损坏的业务附件和资源上限异常仍按现有规则转人工。

DeepSeek 汇总输入只允许包含：

```json
{
  "email_body": "邮件正文",
  "rule_candidates": {},
  "attachments": [
    {
      "file_name": "fault-report.pdf",
      "parse_status": "parsed",
      "extracted_text": "截断后的文本",
      "extracted_json": {}
    }
  ]
}
```

## 9. AI 回复草稿原则

回复草稿模型职责：

- 根据模板和工单缺失字段生成更自然的中文草稿。
- 草稿只用于人工审核，不代表已发送。
- 语气礼貌、简洁。
- 不承诺维修时效、维修结果、费用政策。
- 不加入输入中不存在的客户信息。

输出字段建议：

```json
{
  "subject": "请补充报修信息：RMA202607090001",
  "body": "您好，\n\n我们已收到您的报修邮件，但还需要您补充设备 SN 和故障描述，以便继续处理。\n\n请直接回复本邮件补充。谢谢。",
  "missing_fields": {
    "sn": "缺少设备 SN",
    "problem_description": "缺少故障描述"
  },
  "confidence_score": 0.82,
  "risk_level": "low",
  "suggestions": []
}
```

## 10. LangGraph 后期资料索引

LangGraph 后期定位：

- 邮件报修 AI 工作流编排器。
- 串联规则解析、附件处理、多模态解析、AI 结构化解析、业务校验、工单动作计划、人工复核、回复草稿。
- 不直接写业务最终状态。

推荐节点资料：

| 节点 | 资料需求 |
| --- | --- |
| `body_preprocess_node` | 邮件正文清洗、引用链裁剪、HTML 转文本 |
| `rough_classify_node` | 邮件意图类型、无关邮件关键词、内部转发关键词 |
| `attachment_detect_node` | 普通业务附件类型、大小、是否图片/扫描件；压缩容器仅做工程资料分类 |
| `attachment_extract_node` | PDF、Excel、Word 文本抽取策略；不包含压缩包解压 |
| `ocr_parse_node` | Qwen OCR 输入输出、失败转人工（Qwen API Key 已配置） |
| `vl_parse_node` | Qwen VL 图片理解摘要格式（Qwen API Key 已配置） |
| `ai_full_parse_node` | 当前 AI 解析 Prompt 和 JSON schema |
| `schema_validate_node` | JSON schema、字段类型、置信度范围 |
| `business_validate_node` | SN 校验、客户匹配、缺失字段、冲突字段 |
| `ticket_prepare_node` | service 可执行动作计划 |
| `human_review_interrupt_node` | 人工任务原因、resume payload |
| `reply_draft_node` | 回复模板和 AI 草稿规则 |
| `finalize_node` | Graph 输出摘要、状态、错误 |

工具调用资料：

- IMAP client：邮件拉取、UID、文件夹、失败重试。
- OSS client：上传、下载、预签名 URL、对象 key 规则。
- OCR/VL：图片、扫描件、表格截图、故障截图。
- SN 查询工具：只读查 `sn_assets`。
- 板卡规则工具：只读查 `board_cards`。
- WorkflowService：唯一状态流转入口。
- ManualReviewService：人工任务和 resume 入口。
- ReplyService：草稿、审核、发送入口。

附件安全资料：

- 支持自动解析 `docx/xlsx/csv/txt/html/image/pdf`；压缩容器只识别并归档为工程辅助资料，其他不支持格式仍按现有规则处理。
- 超过 50MB 的附件仍上传 OSS，但停止自动解析并转人工。
- PDF 默认只处理前 15 页，超出部分必须在结果中标记截断。
- 当前不读取压缩包目录，无法判断加密、损坏、内部危险文件或嵌套层级；界面必须显示“未经内容扫描”，该事实本身不转人工。
- 可执行文件、脚本、可疑二进制不自动解析。
- 附件全文或 OCR 大文本不进入节点日志。

## 12. RMA 授权表与海外回复模板

## 13. 测试邮箱与离线安全样例

- 测试 IMAP 收件账号：`rmatest1@accotest.com`。
- 测试 SMTP 发件账号：`rmatest1@accotest.com`；最底层发送前必须验证登录账号与 From 完全一致。
- 唯一允许的测试收件人：`rmatest2@accotest.com`，该邮箱只用于模拟客户接收系统发出的邮件；RMA 测试邮件强制单一 To，Cc/Bcc 为空。
- 邮件拉取只读取 `rmatest1@accotest.com` 的 INBOX 中已经存在的指定测试业务邮件，不通过 `rmatest2 → rmatest1` 发送“客户种子邮件”构造输入。
- 测试主题必须包含 `[TEST ONLY]`，RMA PDF 使用 `rma_authorization_auto_v3_1` 且所有页面带 `TEST ONLY / 测试数据` 水印，只能使用虚构客户、SN、物料、故障和地址。

## 14. 新报修必填字段与公司收货定义

- 新报修客户必填：客户名称、联系人、客户邮箱、报修日期、寄回地址、故障描述、至少一条有效 SN/设备。
- 电话选填；客户编码、客户名称候选、物料编码和物料名称可由 SN 主数据补全。主数据失败是内部人工问题，不向客户追问系统字段。
- `device_received` 只表示公司收到客户寄来的待修设备及纸质 RMA 授权单，不表示客户收到维修完成后的设备。
- 闭单事实链：客户新报修 → 校验无误并发送 RMA → 公司收到待修设备 → 向客户发送收货确认成功 → `closed`。
- 可信内部收货通知必须使用精确邮箱白名单，并通过原邮件 Message-ID 关系关联工单；域名相同本身不构成信任。
