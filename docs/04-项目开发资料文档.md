## 2026-08-12 回复正文与历史引用规则

- 本次回复正文必须来自启用模板；历史引用来自最新有效客户入站邮件的原始 EML，两者职责分离。
- 完整保留父邮件富文本、表格、安全样式和实际CID依赖，但不复制历史普通附件。外链与data image保留原地址/内容，不主动下载或转存。

## 2026-08-11 邮件分类业务规则

| 层级 | 邮件类型 | 建单/关联 | 自动追问/RMA | 人工动作 |
| --- | --- | --- | --- | --- |
| FIRST | 新报修 | 新建标准工单 | 允许 | 异常时介入 |
| FIRST | 回复链新报修 | 同一 EmailThread 下新建业务工单 | 允许 | 无法安全拆分时介入 |
| FIRST | 客户补充 | 合并当前等待资料工单，不覆盖旧值 | 重新校验后决定 | 冲突时介入 |
| SECOND | 元器件替换、叫修、保修状态确认、线程其他问题 | 同线程 FIRST 存在时另建 `manual_business` | 禁止 | 领取、编辑、转派、记录结论、`resolved` |
| THIRD | 入库、维修后发出、客户收货、合同、发票、非我司设备报价 | 仅可留生命周期关联 | 禁止 | 默认不创建 RMA 人工任务 |
| UNKNOWN | 无法可靠识别 | 不建标准工单 | 禁止 | 邮件级任务判断并记录结果 |

多意图以安全业务动作优先：可明确拆出的 FIRST 高于纯 THIRD；“补充旧工单 + 新报修”等当前无法安全拆分的邮件进入 SECOND/UNKNOWN 人工处理，禁止强制自动合并。规则负责邮件头、线程、工单状态、现有 RMA/SN 等确定性事实；AI 负责客户真实诉求和业务语义，最终结果由两者共同决定。

待修设备到达是 THIRD 生命周期事件，不关闭、重开或推进标准工单，也不再生成收货确认邮件。标准工单在 RMA 回复和归档全部成功时闭合；SECOND 工单仅由人工结论置为 `resolved`。

## 2026-08-11 删除业务规则

- 删除本地记录不等于撤销 SMTP、SAP 或已发 RMA 等外部业务动作。生产环境中，只要已存在这些不可逆事实，普通删除必须拒绝。
- 邮件是工单来源、收货证据、关键 source/outbound 关联、已应用解析或已发送回复时不得直接删除；删除工单不反向删除邮件。
- `rma_sent/closed` 工单、已提交的 SourceRequestID/RMA、已发送回复、成功或不确定的外部操作均属于不可逆事实。历史 CallID 仅作审计。仅受控测试库允许在严格门禁下执行本地强制清理。
- 附件若解析结果已应用、字段审计仍引用或 AI 结果被回复使用，则必须拒绝独立删除。共享 OSS 对象只解除当前引用，不删除物理文件。

## 2026-08-05 参考邮件规范

- 规范参考：`RMA2026070910南京矽力微电子技术有限公司.eml`。国内 RMA 正文采用“Dear 联系人、RMA 表格见附件、三项寄送/工期提示、动态寄回地址、Miya 完整签名、中英文保密声明”的 v2 模板。
- RMA 邮件主题不是固定 `Re: 原主题`，而是与 RMA PDF 附件文件名一致（不含 `.pdf`）；追问信息邮件才采用 `Re: 原主题`。
- 主题是否变化不影响邮件线程。客户端归并依赖 `In-Reply-To`、`References` 和实际父 Message-ID；正文追加的历史对话用于人工阅读与不完整客户端兼容。
- PDF 的 `Requested by`、`Approved by`、`System Information`、`Software Revision` 等当前没有确定数据源，继续留空。禁止为了“看起来完整”而使用 AI 或默认值填充。
- 参考生成文件 `output/rma-subset-visual.pdf` 为本轮字体子集视觉样例，不是客户业务附件，不得外发。

尚未提供客户编码全量表、SN 全量表和海外客户清单。当前实施原则是“不造数、不猜测”：已有 SN 镜像继续使用；旧政策客户范围保持待确认；真实工单无法确定国内/海外时进入人工。海外范围一旦由政策或人工确认，使用唯一北京默认维修寄回路线，不依赖邮件语言或板卡字段。

字段语义：

- 板卡：`board_code/board_name`，只决定维修寄回路线。
- SAP 物料：`material_code/material_name`，来自 SN 资产校验并写入 SAP。
- 客户方邮寄：工单 `mailing_address/contact_person/contact_phone`，写入 SAP。
- 维修收件：明细 `return_address/return_contact/return_phone/return_postal_code`，快照后用于 RMA 正文。

## 2026-07-28 客户政策、地址与 RMA 规则

价格只来自本地客户政策快照，SAP 不回填价格：

- 默认超保：`1200 CNY`，税率 `13%`。
- 快递费字段：`one-way charge/单次收费`。
- 永久免费：迁移导入 20 个客户代码，维修费为 0。
- 包年免费：迁移导入 6 个客户代码，但在逐客户补齐生效/失效日期前保持停用。
- 异常超保价格：迁移导入 10 个客户代码，其中 `CM00315` 为 `165 USD`，其余按附件价格/税率保存。
- 同一日期同时命中免费和异常价格、多个有效政策或强制人工规则时，不推断优先级，进入人工复核。
- RMA PDF 的逐 SN 价格、币种、税率和合计来自 `export_sap.policy_snapshot`，禁止回退到 SAP 价格或全局 PDF 默认价。

地址规则：

- 国内板卡编码和名称精确匹配时采用对应路线；名称不精确时，仅当同一编码的全部启用规则都指向同一地点才可自动采用。
- 未提供板卡、仅有板卡名称、编码跨地点冲突或收件资料不完整时转人工，不允许默认天津。
- 海外客户使用唯一启用的北京默认路线，不查询板卡。
- 一个工单可保存不同明细的维修寄回快照；寄回路线不影响 SAP 客户方邮寄字段。RMA 签发前如仍有未解析路线则转人工。

品牌与称呼：

- 客户政策可设置 `reply_salutation`、`hide_company_name` 和 `force_manual_review`。
- 隐藏公司名时，普通中文回复可使用模板库中的中性基础模板。当前固定 RMA PDF 尚无经业务确认的中性版本，因此此类 RMA 在生成附件前进入 `RMA_NEUTRAL_PDF_TEMPLATE_REQUIRED` 人工节点，绝不发送可能泄露公司名的附件；不同 SN 的品牌规则不一致同样进入人工复核。
- 所有追问、受理、人工回复和 RMA 回复均必须使用模板并保留原线程回复头；设备收货只记审计事实，不发送确认邮件。

RMA 编号规则：本系统不分配编号，只接受 10 位 `yyyyMMddNN`；日期无效、序号 `00` 或包含非数字字符均转人工。一个工单多个 SN 可共用一个 RMA；同工单回填多个 RMA 时不自动生成 PDF、不自动回复。

## 2. 邮件类型和意图类型

当前代码使用或规划的邮件意图：

| 意图 | 说明 | 当前处理 |
| --- | --- | --- |
| `new_repair` | 新报修请求 | 进入解析、建单或人工复核 |
| `customer_supplement` | 客户补充信息 | 关联线程和工单，线程级重新聚合 |
| `repair_thread_other` | 报修回复链其他问题 | SECOND，关联上下文并通知人工，不自动修改 FIRST |
| `rma_sent` | RMA 已发送 | 记录外发事件，不重复生成 RMA |
| `device_intake_received` | 待修设备到达/入库 | THIRD，仅留存生命周期事件，不关闭工单 |
| `internal_forward` | 内部转发 | 进入 AI 判断和人工兜底 |
| `irrelevant` | 明确无关邮件 | 可跳过业务处理 |
| `unknown` | 类型不明确 | 进入 AI 或人工复核 |
| `outbound_reply` | 系统外发回复归档 | 出站邮件归档 |

后续可扩展意图：

- `device_intake_received`（仅历史/生命周期分类，不是闭单事件）
- `repair_device_returned`
- `customer_receipt_confirmed`
- `export_or_sync_notice`

这些后续意图需要先完成业务事件契约和页面入口；优先由现有状态、操作及系统日志聚合表达，只有证据表明无法满足约束和查询时才评估新表。

## 8. AI 解析 Prompt 原则

系统提示词原则：

- AI 是结构化解析助手，只能输出 JSON。
- 规则解析只作为候选上下文，不直接决定最终业务类型。
- 必须输出意图、字段、明细、缺失字段、冲突字段、置信度、字段置信度、证据。
- 不得编造不存在的信息。
- 不确定字段必须放入 `missing_fields` 或 `conflict_fields`。
- 低置信或需要人工时，必须给出人工复核方向。

输出字段建议：

```json
{
  "intent_type": "new_repair",
  "extracted_fields": {
    "customer_name": "示例科技有限公司",
    "contact_person": "张三",
    "contact_phone": "13800000000",
    "contact_email": "zhangsan@example.com",
    "problem_description": "设备无法启动"
  },
  "extracted_items": [
    {
      "line_no": 1,
      "sn": "ABCD123456",
      "material_code": null,
      "material_name": null,
      "quantity": 1,
      "failure_description": "设备无法启动"
    }
  ],
  "missing_fields": {},
  "conflict_fields": {},
  "confidence_score": 0.86,
  "field_confidences": {
    "sn": 0.9,
    "problem_description": 0.85,
    "contact_email": 0.8
  },
  "evidence": {
    "sn": "原文片段中的 SN ABCD123456",
    "problem_description": "原文片段中的设备无法启动"
  },
  "confidence_reasons": [
    "邮件包含明确报修关键词",
    "SN 和故障描述完整"
  ],
  "manual_review_direction": null,
  "original_evidence": [
    "设备 SN：ABCD123456",
    "故障现象：设备上电后无法启动"
  ]
}
```

禁止：

- 输出非 JSON。
- 输出 Markdown 包裹 JSON。
- 使用模型猜测客户编码。
- 隐瞒冲突。
- 把低置信结果标成高置信。

多 Provider 支持：

- DeepSeek 是邮件级业务结构化解析 Provider，汇总正文、规则候选和附件解析结果。
- Qwen 已作为附件级 Provider 接入。`txt/csv/html/docx/xlsx` 和文本型 PDF 先本地抽取再交给 Qwen；图片和扫描 PDF 使用 OSS 短期预签名 URL 调用 Qwen VL。
- 文本类附件使用 `QWEN_MODEL`，图片和扫描 PDF 使用 `QWEN_VL_MODEL`；VL 未配置时转人工，不回退到文本模型。
- DeepSeek 不接收附件二进制。管理员受限 AI JSONL 可保存完整文本语义用于 Prompt 优化，但不得保存签名参数、密钥、认证头、data/base64 或附件二进制。

附件级输出格式：

```json
{
  "file_type": "pdf",
  "summary": "附件描述一台设备无法启动",
  "key_points": ["包含设备 SN", "包含故障现象"],
  "extracted_fields": {
    "sn": "ABCD123456"
  },
  "extracted_items": [],
  "raw_text": "已截断的附件抽取文本",
  "warnings": ["PDF_TRUNCATED_TO_15_PAGES"],
  "truncated": true
}
```

附件处理规则：

| 文件类型 | 处理方式 | 默认限制 |
| --- | --- | --- |
| `txt`、`csv`、`html` | 本地解码/表格抽取/HTML 转文本后调用 Qwen | 模型输入最多 20000 字符 |
| `docx` | 从 OOXML 提取段落后调用 Qwen | 损坏或加密文件转人工 |
| `xlsx` | 只读抽取前 10 个 sheet，每表前 200 行、40 列 | 超出范围在结果中提示截断 |
| 图片 | OSS 预签名 URL 调用 Qwen VL | 单文件自动解析上限 50MB |
| PDF | 前 15 页先抽文本；无文本时生成前 15 页预览并调用 Qwen VL | 超页标记 `truncated=true` |
| ZIP、RAR、7Z、TAR、TAR.GZ、TGZ、GZIP | 扩展名、MIME、魔数联合识别后原样私有归档 | 不读取目录、不解压、不调用 Qwen；`parse_status=skipped` |

异常结果约定：

- 超过 50MB：保留 OSS 对象，`parse_status=needs_manual_review`，`parse_error=FILE_TOO_LARGE_FOR_AUTO_PARSE`。
- 装饰性 inline 图片：归档前按尺寸阈值剔除，不创建独立 OSS/附件/Qwen 记录；业务内嵌图片正常归档和预览。
- 工程辅助压缩附件：`parse_status=skipped`、`parse_error=null`、`security_status=unscanned_archive`，跳过原因为 `ENGINEERING_REFERENCE_NOT_REQUIRED`，不得触发人工复核或客户追问。
- 其他不支持类型：`parse_status=unsupported`，`parse_error=UNSUPPORTED_FILE_TYPE`。
- 未归档附件：`parse_status=needs_manual_review`，`parse_error=ATTACHMENT_NOT_ARCHIVED`。
- Qwen 超时、服务错误或 JSON 校验失败：保留本地抽取文本和 warning，对应附件转人工，不阻断 DeepSeek 处理邮件正文。
- Qwen 常见形状漂移（对象型摘要、单对象明细、字符串型列表/布尔值）先归一化到附件标准 JSON；无法归一化时保留脱敏后的完整语义请求和模型响应，禁止记录 API Key、二进制 data URL 或完整 OSS 签名查询串。
- 超时、429 和 5xx 最多重试 3 次；模型返回无效 JSON 时只允许一次纠正调用，每次尝试均写 `ai_call_logs`。
- DOCX/XLSX 的 OOXML 本地抽取继续使用现有资源限制；独立压缩附件不打开成员目录，因此不配置压缩层级、成员数量或解压大小。加密 PDF、损坏的业务附件和资源上限异常仍按现有规则转人工。

DeepSeek 汇总输入只允许包含：

```json
{
  "email_body": "邮件正文",
  "rule_candidates": {},
  "attachments": [
    {
      "file_name": "fault-report.pdf",
      "parse_status": "parsed",
      "extracted_text": "截断后的文本",
      "extracted_json": {}
    }
  ]
}
```

## 14. 新报修必填字段与公司收货定义

- 新报修客户必填：客户名称、联系人、客户邮箱、报修日期、寄回地址、故障描述、至少一条有效 SN/设备。
- 电话选填；客户编码、客户名称候选、物料编码和物料名称可由 SN 主数据补全。主数据失败是内部人工问题，不向客户追问系统字段。
- `device_intake_received` 只表示待修设备到达/入库；它与 `customer_repaired_device_received`（客户收到维修后设备）严格区分，两者都不触发 RMA 生成或闭单。
- 闭单事实链：客户新报修 → 校验并取得正式 RMA → PDF 关键字段校验 → 原链模板回复 SMTP 成功并保存 Message-ID → PDF 与出站 EML 归档核验 → `closed`。
- 可信内部收货通知必须使用精确邮箱白名单，并通过原邮件 Message-ID 关系关联工单；域名相同本身不构成信任。

## 15. 2026-07-27 当前代码口径补充

- 当前 9 个主状态为 `new_email`、`parsed`、`need_customer_info`、`auto_replied`、`manual_review`、`ready_for_export`、`rma_sent`、`error`、`closed`，不存在 `exported` 主状态。

- 邮件线程只按 `References/In-Reply-To → Message-ID` 精确关联；主题和发件域不能自动合并，线程合并 API 已返回 410。
- 人工复核不得直接关闭工单：当前 seed/迁移只允许 `rma_issued_and_archived` 闭单。
- 自动追问目前包括首次事件驱动追问和人工触发；没有按时间周期自动创建第二轮/多轮催补任务。
- SQL Server Relay 通过独立适配层完成 ODBC SN 全量快照、同工单多 SN 单事务写出和 SourceRequestID/RMA 批量轮询；远端唯一身份为本地预生成的 SourceRequestID。

同一 RMA 可关联同客户、同报修日期的多个工单，但每个工单仅使用自己的 SN 生成附件，并回复各自原邮件线程。客户代码或报修日期不一致时必须转人工，不得自动合并。
- ZIP/RAR/7Z/TAR/GZ 的 `unscanned_archive` 只表示“未扫描”，不表示安全文件；下载后必须在隔离环境处理。
